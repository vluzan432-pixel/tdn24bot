# Бот-розклад для групи

Тепер бот — на всю групу, з нагадуваннями перед парами і нотатками/дедлайнами.

## Що нового

- **Мультикористувацькість.** `/start` пропонує обрати свою групу зі списку
  (беруться зі `schedules.json`). Кожен одногрупник реєструється сам, дані
  (група, нагадування, нотатки) зберігаються окремо на кожен `chat_id`.
- **Нагадування перед парою.** Кнопка "🔔 Нагадування" під розкладом — обрати
  за скільки хвилин попереджати (5/15/30) або вимкнути зовсім.
- **Нотатки/дедлайни до пари.** Кнопка "📝 Нотатка: <предмет>" під розкладом
  дня — бот попросить текст і збереже його; він з'являється прямо під парою
  наступного разу. `/notes` — список усіх своїх нотаток, `/delnote ID` —
  видалити.

## Архітектура (чому саме так)

Безкоштовний Render "засинає", якщо 15 хв немає вхідних HTTP-запитів. Це
ламає бота, що працює через **polling** (постійне опитування Telegram) —
Render просто вб'є процес разом із цим циклом. Тому:

1. Бот тепер працює через **webhook**: Telegram сам стукає в наш HTTP-ендпоінт,
   коли є нове повідомлення. Вхідний запит будить заснулий сервіс за секунди.
2. Нагадування ж нікому не пишуть, поки хтось не написав боту — тому потрібен
   зовнішній "будильник", який не залежить від активності користувачів.
   Це робить **GitHub Actions**: у публічному репозиторії cron-задачі там
   безлімітні й безкоштовні. Він раз на 5 хв стукає в `/cron` на нашому боті —
   це одночасно і будить Render (якщо заснув), і каже боту: "перевір, кому
   час нагадати про пару".
3. **База даних — не локальний файл.** У Render безкоштовний веб-сервіс має
   *ephemeral* (тимчасову) файлову систему: будь-який локальний файл
   (включно з SQLite) стирається щоразу, коли сервіс засинає/перезапускається/
   передеплоюється. Тому дані користувачів, групи й нотатки живуть у
   [Turso](https://turso.tech) — безкоштовній хмарній базі, сумісній з SQLite
   (бібліотека `libsql` в Python має майже той самий інтерфейс, що й
   вбудований `sqlite3`, тож код бота виглядає так само, як зі звичайною
   SQLite).

Усе це — стандартна, повністю безкоштовна схема, без картки на жодному з
трьох сервісів (Render / GitHub / Turso).

## Крок 1. Turso (база даних)

```bash
# Встановити CLI (одноразово)
curl -sSfL https://get.tur.so/install.sh | bash

turso auth login
turso db create schedule-bot
turso db show schedule-bot --url          # -> TURSO_DATABASE_URL
turso db tokens create schedule-bot       # -> TURSO_AUTH_TOKEN
```

Якщо не хочеш ставити CLI — на [turso.tech](https://turso.tech) є й
веб-кабінет, де можна створити базу і токен без термінала.

Схему таблиць бот створює сам при першому запуску (`db.init_db()`), нічого
руками накатувати не треба.

## Крок 2. Підготувати schedules.json (усі групи одразу)

Замість одногрупового `schedule.json` тепер один файл на всі групи:

```bash
pip install -r requirements.txt
python build_schedules.py "розклад.docx" schedules.json "ТДН-24" "ТДН-25" "ТДН-26"
```

Перелічи всіх, кого хочеш підключити. Коли деканат викладе новий `.docx` —
просто перезапусти цю команду й задеплой оновлений `schedules.json` разом з
рештою коду.

## Крок 3. Render (сам бот)

1. Заливаєш весь код (разом з `schedules.json`, `zoom_links.json`) у
   GitHub-репозиторій.
2. На [render.com](https://render.com) → **New → Web Service** → підключаєш
   репозиторій.
3. Налаштування:
   - Build command: `pip install -r requirements.txt`
   - Start command: `python bot.py`
   - Instance type: **Free**
4. Environment → додаєш змінні:

   | Змінна | Значення |
   |---|---|
   | `BOT_TOKEN` | токен від @BotFather |
   | `WEBHOOK_BASE_URL` | твоя адреса на Render, напр. `https://schedule-bot-xxxx.onrender.com` (Render покаже її після першого деплою — після цього просто онови змінну й задеплой ще раз) |
   | `WEBHOOK_SECRET` | будь-який довгий випадковий рядок |
   | `CRON_SECRET` | інший довгий випадковий рядок |
   | `TURSO_DATABASE_URL` | з кроку 1 |
   | `TURSO_AUTH_TOKEN` | з кроку 1 |

5. Deploy. У логах має з'явитись `Webhook встановлено на https://.../webhook/...`.

## Крок 4. GitHub Actions (будильник + keep-alive)

У репозиторії вже є `.github/workflows/keepalive.yml` — лишилось додати один
секрет:

1. Repo → **Settings → Secrets and variables → Actions → New repository secret**
2. Ім'я: `BOT_CRON_URL`
   Значення: `https://твій-бот.onrender.com/cron?secret=ЗНАЧЕННЯ_CRON_SECRET`
   (той самий `CRON_SECRET`, що і в Render)

Готово — раз на ~5 хв GitHub сам стукатиме в бота. Перевірити вручну можна
кнопкою "Run workflow" на вкладці Actions.

⚠️ GitHub вимикає (не видаляє) scheduled-workflow, якщо в репозиторії 60 днів
не було жодного коміту — просто зроби будь-який коміт раз на пару місяців,
якщо репо зовсім не чіпається.

## Обмеження цієї безкоштовної схеми

- Перше повідомлення після сну Render може прийти із затримкою ~30-60 сек
  (сервіс прокидається) — для навчального бота це не критично.
- GitHub Actions cron може запізнюватись на кілька хвилин у пікові періоди —
  нагадування за 15/30 хв це не ламає, але точну хвилину в хвилину не обіцяй.
- Часовий пояс — системний час сервера Render. Для Європи/Києва зазвичай ок,
  за потреби можна додати `zoneinfo`.

## Команди бота

- `/start` — обрати групу (перший раз) або показати розклад на сьогодні.
- `/group` — змінити групу.
- `/notes` — список усіх своїх нотаток. `/delnote ID` — видалити одну.
- `/find запит` — знайти предмет, викладача або аудиторію в найближчі 14 днів.
- `/materials [предмет]` — матеріали для групи; кнопка «⚙️ Налаштування»
  вмикає вечірній розклад на завтра та звичайні оголошення.
- Кнопки під розкладом: навігація по днях, Zoom-посилання, нотатка до пари,
  налаштування нагадувань.

## Адмін-команди та права

Головний адміністратор — це `ADMIN_IDS` у змінних Render. Він вводить
`/admin`, щоб побачити доступні дії, та `/staff`, щоб переглянути заступників.

- `/grant ID schedule,announce` — видати конкретні права учаснику.
- `/revoke ID` — забрати всі додаткові права.
- `/announce текст` або `/urgent текст` — звичайне або термінове оголошення
  для своєї групи. Після команди можна вказати назву іншої групи першим словом.
- `/material Предмет | Назва | https://посилання` — додати матеріал.
- `/poll Питання | Варіант 1 | Варіант 2` — розіслати опитування.

Права: `schedule` (редагування розкладу), `announce` (оголошення),
`materials` (матеріали), `polls` (опитування). Тобто заступнику можна дати,
наприклад, лише `announce,polls`.
